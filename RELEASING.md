# Releasing bluepencil

The CLI, core library, language server, VS Code extension, and npm package `bluepencil-node` use the same release version. The `version_sync` test in `crates/bluepencil/tests` fails CI when any of them disagrees with `Cargo.toml`.

1. Update the workspace version and `bluepencil-core` path dependency in `Cargo.toml`, the VS Code version in `editors/vscode/package.json` and its lockfile, and `CHANGELOG.md`. In `crates/bluepencil-node`, run `npm version X.Y.Z --no-git-tag-version` and then `npm run build`, which regenerates `index.js` with the version its per-platform binding packages must carry; commit both.
2. Run the checks used by CI: `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --all-targets`, `cargo +1.88 check --workspace`, `cargo deny check`, `bash scripts/build-pages.sh`, and `npx @vscode/vsce package` from `editors/vscode` after `npm ci`. Wait for CI and Audit to pass on `main`.
3. Check `dist plan --tag=vX.Y.Z`, then create and push the tag with `git tag -a vX.Y.Z -m 'bluepencil vX.Y.Z'` and `git push origin vX.Y.Z`. The release workflow builds binaries and installer scripts for macOS, Linux, and Windows, packages the VSIX, and attaches them with generated Homebrew formulae before publishing the immutable GitHub release. The same tag runs `release-node.yml`, which refuses a tag that does not match `package.json`, skips a version already on npm, and otherwise builds every declared target and publishes `bluepencil-node`. To retry, run it by hand against the tag.
4. The release workflow pushes `bluepencil.rb` and `bluepencil-lsp.rb` to `writerslogic/homebrew-tap` when `HOMEBREW_TAP_TOKEN` has write access there. Without that secret, copy both formula assets from the GitHub release into the tap and push them manually. Check the generated install methods before publishing: the 0.2.0 formulae needed their empty alias mapping removed. Verify both formulae with `brew audit --strict --online`, `brew install`, and `brew test`.
5. Publish crates.io packages in dependency order: `cargo publish -p bluepencil-core`, then `cargo publish -p bluepencil` and `cargo publish -p bluepencil-lsp` once the core version is available in the registry. `bluepencil-node` and `bluepencil-web` are not published as Rust crates.
6. To publish the extension in the VS Code Marketplace, upload the release VSIX under the `WritersLogic` publisher or add a `VSCE_PAT` repository secret with Marketplace manage permission and run `publish-vscode.yml` against the release tag. Check that the Marketplace lists the new version before linking it from the README and guide. Version 0.2.0 uses a [separate VSIX release](https://github.com/writerslogic/bluepencil/releases/tag/vscode-extension-2026-10-25) because its binary release was already immutable when the VSIX was packaged.

Verify the public writing desk at `https://writerslogic.github.io/bluepencil/` and the guide at `https://writerslogic.github.io/bluepencil/docs/` after the Docs workflow finishes.

The site build requires `npm --prefix docs/playground ci` before `bash scripts/build-pages.sh`. Run the [browser integration checks](CONTRIBUTING.md#browser-writing-desk) before publishing changes to the writing desk.
